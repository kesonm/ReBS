# 策略参数与因子目录 v1

目录由 `backend/strategy_catalog.json` 驱动工作台，包含 **226 个因子定义、171 个全局参数、18 个表达式函数、6 个策略模板**。它覆盖当前项目的现货行情、逐笔成交、盘口、账户与后续扩展边界，是可扩充的第一版目录，不声称穷尽所有数学公式或交易策略。

## 能力边界

所有因子的 `computeStatus` 都是 `definition`：当前可检索定义、查看公式与单位、编辑参数、组合规则和保存版本；目录本身不计算因子、不启动采集、不回测、不发出订单。表达式预览使用用户明确提供的输入序列，不将人工样本标为真实行情。

`dataStatus` 只表示数据依赖：

| 状态 | 因子数 | 含义 |
| --- | ---: | --- |
| `available` | 129 | 项目已有相应数据接口；不代表已实现因子计算或存在完整本地历史 |
| `requires_history` | 79 | 需要连续录制、对齐、策略账本或运行事件历史 |
| `not_connected` | 18 | 需要另接数据源，或者当前聚合数据根本无法推导 |

全局参数按数据与时间、信号与公式、资金与仓位、手续费与滑点、订单执行、风险控制、回测与评估、运行与恢复分组。所有参数都保存类型、默认值、单位、说明及范围/枚举。策略配置不包含 API Key、Secret、Passphrase 或网页访问口令。

## 公式约定

- `O/H/L/C/V/A` 为现货开高低收、基础币成交量、报价币成交额。`p_i/q_i` 为成交价和基础币成交数量。`s_i=+1` 是主动买入，`−1` 是主动卖出。
- “比例”使用小数：`0.01=1%`；“百分比”已乘 100；`1 bp=0.01%`。表达式 `pct_change` 返回小数比例。
- 时间窗口统一为交易所事件时间 `(t−w,t]`；K 线窗口按完整样本计数。交易所时间、网络接收时间和策略处理时间分别记录。
- 表达式 `std(series,n)` 使用总体标准差（`ddof=0`）。目录中某些因子另有可编辑 `ddof` 定义，未来计算引擎需要按实例参数实现，不能忽略它。
- EMA 使用 `α=2/(n+1)`；表达式函数以第一个完整窗口 SMA 初始化。目录 EMA 因子还列出 `first` 初始化供未来计算引擎实现。RMA/Wilder 使用 `α=1/n`，初值是完整窗口均值。嵌套指标必须预热完整依赖链。
- 样本不足、非有限数、分母为零和无效价格默认返回缺失，不填成 0。RSI 全平、CMF 零振幅等有明确约定的特例在对应因子说明中列出。
- 上穿：前一时间点 `a≤b` 且当前 `a>b`；下穿：前一时间点 `a≥b` 且当前 `a<b`。必须使用相邻的有效时间点，不跨数据缺口寻找交叉。唐奇安突破默认排除当前 K 线。
- 每个因子的 `formula` 是可读数学定义，不是直接交给 Python `eval` 的代码。用户规则使用工作台限定的表达式语法和函数。

## 逐笔与盘口

逐笔流使用 `trades-all`，按 `instId+tradeId` 去重。REST 最近成交可能合并成交，不能替代完整逐笔历史。浏览器中的有限条数列表也不是可回放的历史数据。大单阈值明确使用报价币成交额，数量口径明确使用基础币。

`books` 是最多 400 个价位的 L2 聚合盘口，需要完整快照及连续增量重建。它不能唯一推导逐委托撤单数量、隐藏量或本订单真实排队位置；这些因子显式标为未接入。盘口减量不能直接称为撤单量。

OFI 使用 Cont–Kukanov–Stoikov 一档事件定义；聚合快照可能合并底层事件，不能宣称重现逐委托事件。扫单成本只是在当前可见深度上的估计，深度不足就返回缺失，不臆造更远档位。

现货资产从余额明细读取，不能把合约 `positions` 当作现货持有数量。策略资金、持仓、费用及订单占用必须在独立账本中核算；未成交订单不能计为已持仓。

## 模板与后续运行约束

6 个模板覆盖双均线交叉、RSI 均值回归、唐奇安突破、逐笔失衡与 CVD、盘口压力、波动和量能过滤趋势。所有阈值只是示例定义，并非已经验证的获利参数。

订单定义包括基础币/报价币数量口径、限价/市价、有效方式、部分成交、客户订单幂等键、未知状态查单、有限重试、撤单确认和限频。当前手工模拟交易接口固定 `base_ccy`，目录中 `quote_ccy`、IOC/FOK 等选择是未来执行器定义，不表示手工接口已实现。

风控定义包括止损/止盈价格源、净费用口径、ATR/比例/金额阈值、移动止损、日亏损、最大回撤、持有时间及断线暂停。填入“启用”只保存意图；工作台还没有运行器或交易所保护单。

回测定义要求：收盘信号不能在已经过去的收盘价成交、信号与执行时间分离、同根止盈止损冲突有明确顺序、费用与价差不重复扣除、参数样本内外分离、拒绝未来数据、记录数据集指纹。重启恢复须先核对订单与成交，不能重发上一事件。
